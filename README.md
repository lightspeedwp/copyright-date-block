# Copyright Date Block

A lightweight WordPress block that keeps the copyright line on your site accurate.
It ships with sensible defaults, optional start-year support, and server-side rendering so the front end always shows the current year.

## Features
- Always displays the current year without manual updates.
- Optional starting year toggle to show a range such as `2020–2024`.
- Block supports text color and font size controls out of the box.
- Server-rendered output keeps the published site in sync even if content is cached.

## Requirements
- WordPress 6.7 or newer.
- PHP 7.4 or newer.
- Node.js 20.x and npm (for local development; matches the CI workflow).

## Installation
1. Clone or download this repository into your WordPress installation under `wp-content/plugins/copyright-date-block`.
2. Run `npm install` inside the plugin directory.
3. Build the production assets with `npm run build`.
4. Activate **Copyright Date Block** from the Plugins screen in WordPress.

To produce a distributable zip, run `npm run plugin-zip` after building. The zip is created in the project root.

## Usage
1. Open the block editor for a post, page, or template.
2. Insert the **Copyright Date** block (search for "copyright").
3. Optional: Enable **Show starting year** in the block settings panel and enter the year your site launched.
4. Publish or update the content. The block renders © followed by either the current year or your configured range.

The block’s markup is generated by `src/render.php`, which compares the saved fallback year with the current year and updates the output automatically on the front end.

## How to use the plugin (step-by-step)

1. Install and activate the plugin in your WordPress site (see Installation above).
2. Edit a post/page or open the Site Editor (Appearance → Editor) to add the block to a template part.
3. Add the block where you want the copyright line to appear.

4. Configure the block settings in the right-hand inspector:

   - Show starting year: toggle on to include a starting year.
   - Starting year: enter the 4-digit year your copyright begins (e.g. `2020`).
   - Text color / font size: use the block controls to match your theme.

5. Save or publish. The frontend renders a server-side-generated copyright line that looks like one of the following examples:

Examples

Single year (site launched this year):

   © 2025

Range when starting year is provided and older than current year:

   © 2020–2025

If you need to include the block directly in a PHP template instead of via the editor, you can render it like any other block by calling `do_blocks()` on content that contains the block markup. A minimal example (theme template file) would look like:

   <?php
   echo apply_filters( 'the_content', '<!-- wp:copyright-date-block/copyright-date {"showStartingYear":true,"startingYear":2020} /-->' );
   ?>

The plugin's `src/render.php` handles the server-side rendering so the final output is always the up-to-date year.

## Development

`npm start` – Run the development build with file watching and block editor hot reloading.

`npm run build` – Generate production-ready assets (also used by CI).

`npm test` – Execute unit tests located in `src/utils/*.test.js`.

`npm run lint:js` / `npm run lint:css` – Lint JavaScript and CSS using the WordPress coding standards.

`npm run env start` / `npm run env stop` – Spin up or tear down a local WordPress environment via `@wordpress/env`.

When contributing changes, please run the linters and tests before opening a pull request. The GitHub Actions workflow mirrors this sequence (lint → test → build → package).

## CI / Release workflow

The repository includes two CI workflows:

- `ci.yml` — runs on pushes and pull requests to `main`/`master` and performs lint, tests, build, and creates a plugin zip (used by PR validation).
- `release-on-tag.yml` — runs when a Git tag is pushed and will create a GitHub Release containing the generated plugin zip.


Recommended local commands before tagging a release:

   # install deps (use --legacy-peer-deps if required)
   npm install

   # run linters and auto-fix where possible
   npm run lint:fix

   # run tests
   npm test

   # build and create zip
   npm run build
   npm run plugin-zip

After tagging and pushing the tag, GitHub Actions will publish a Release that includes the zip.
